# ochk

**Type-aware bug finder for OCaml.**

`ochk` reads the typed `.cmt` files dune already produces and reports bugs
that need type information to find, not style issues. It works on any dune
project with no code changes:

```sh
dune build
ochk _build/default
```

```
File "src/portfolio.ml", line 42, characters 10-11:
Warning SL002 [compare-abstract]: polymorphic (=) on int SM.t; SM.t is abstract, so the result depends on its internal representation. Use SM.equal instead.
```

Requires OCaml 5.3. `ochk` must be built with the same compiler as the code it
checks (it says so clearly if not).

## Rules

The first family of rules catches **polymorphic comparison** used where it is
a bug:

| Rule | Name | Default | Flags |
|---|---|---|---|
| SL001 | compare-functional | error | values containing functions: `=` raises `Invalid_argument` at runtime |
| SL002 | compare-abstract | warning | types that are, or hide, a `Map`, `Set`, `Hashtbl`, `Buffer`, lazy value or object: equal contents can compare as different |
| SL003 | compare-generic | off (`--generic`) | type variables: generic code relying on polymorphic compare |
| SL004 | compare-opaque | off (`--opaque`) | abstract types that are safe underneath (an `int`, a `string`) or not visible: works today, but bypasses the module's own `equal` |

Abstract types are judged by what they hide. ochk follows them to their
definition, in the same file or in the defining module's `.cmt` (dune builds
and installs these), so `Id.t = int` is quiet while `Env.t = int StringMap.t`
is SL002, and an abstract type hiding a closure is SL001.

Checked: `=` `<>` `<` `>` `<=` `>=` `compare` `min` `max` `List.mem`
`List.assoc` `List.assoc_opt` `List.mem_assoc` `List.remove_assoc`
`Hashtbl.hash`, including when passed as values (`List.sort compare fs`).

It looks through nested types (a record holding a map, a list of closures,
`Seq.t`) and stays quiet where comparison is fine:

- comparisons against constants (`l <> []`, `x = None`, `(a, b) = ([], [])`)
- types that are abstract only on paper (`Uchar.t`, `Unix.file_descr`)
- code generated by ppx derivers
- generic code (locally abstract types, functor parameters) unless you pass
  `--generic`

Planned rules: `=` on floats (NaN), `Hashtbl.hash` on types with a custom
equality, polymorphic `Hashtbl` keyed by abstract types.

## Usage

```sh
ochk [--generic] [--opaque] [--only SL001,SL002] [--format text|json] [PATH...]
```

Exit code: 0 = clean, 1 = findings, 2 = tool error.

Suppress a finding:

```ocaml
let same = (f = g) [@ochk.allow "SL001"]   (* one expression *)
let x = ... [@@ochk.allow]                 (* one binding, all rules *)
[@@@ochk.allow "SL003"]                    (* whole file *)
```

## The `ostd` library

This repo also contains `ostd`, a small extension of Stdlib: a few missing
`List`/`String`/`Option`/`Result`/`Map`/`Set` functions, a persistent `Heap`
and `Deque`, and `Ostd.Safe`, which shadows the comparison operators so
`m1 = m2` on maps becomes a compile error:

```ocaml
open Ostd.Safe
let _ = m1 = m2                (* type error *)
let _ = SM.equal Int.equal m1 m2
let _ = Poly.( = ) a b         (* explicit escape hatch *)
```

What it includes and why: [`docs/gaps.md`](docs/gaps.md).
